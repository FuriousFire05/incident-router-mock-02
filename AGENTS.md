# Assessment repository instructions

Prioritize required behavior, correctness, validation, and successful submission.

- Read the existing code and tests before making broad changes.
- Keep architecture simple and preserve existing public behavior unless the task says otherwise.
- Prefer focused changes over rewrites.
- Add or update tests for required behavior.
- Do not hardcode secrets.
- Before reporting completion, run the repository's tests and inspect the actual diff.
- If using an AI coding agent, first report the absolute repository path and current branch and confirm they match the intended assessment repository.
